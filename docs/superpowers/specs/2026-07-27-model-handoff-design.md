# SmartZip 跨模型交接设计

## 目标

在 Codex 额度可用时优先使用 Codex；额度用尽时，允许 EchoBird 中的第三方模型在**新的会话**中继续同一个 SmartZip 工作区。项目进度不得依赖任何供应商的会话 ID、响应项 ID 或私有会话历史。

## 非目标

- 不修改 SmartZip 的运行逻辑、测试逻辑或发布产物。
- 不尝试编辑 EchoBird 已编译的代理程序。
- 不让两个模型同时编辑同一工作区。

## 当前工作区事实

- 当前分支为 `main`。
- 现有未提交修改仅在 `tests/RunCmdCapture.Fragment.ahk`：内容与 `HEAD` 相同，差异仅为 CRLF 被转换为 LF。交接流程必须把它视为待确认的格式变更，而非功能实现。
- 项目测试入口和完整基线命令记录在 `tests/README.md`。

## 架构

项目内文件是唯一可移植的交接状态，优先级如下：

1. Git 工作树和提交历史：真实源码状态。
2. `docs/continuity/ACTIVE_TASK.md`：唯一当前任务、进展、下一步和验证状态。
3. `docs/continuity/DECISIONS.md`：已经确认且不应由接手模型擅自推翻的决定。
4. `docs/continuity/RESUME_PROMPT.md`：新会话的固定启动提示词。
5. 根目录 `AGENTS.md`：所有模型的读取顺序和工作区安全规则。

## 切换流程

### 离开当前模型前

1. 运行 `git status --short`，记录未提交文件及其性质。
2. 更新 `ACTIVE_TASK.md`：目标、已完成、未完成、涉及文件、最后运行的命令和结果。
3. 将稳定结论写入 `DECISIONS.md`。
4. 不记录 API 密钥、密码、会话 ID 或复制的敏感日志。

### 第三方模型接手

1. 在 EchoBird 中创建**新会话**，不使用 Codex 旧会话的继续/恢复功能。
2. 粘贴 `RESUME_PROMPT.md`，让模型先读取 `AGENTS.md`、三个交接文件、`README.md`、`tests/README.md` 并运行 `git status --short`。
3. 接手模型必须先给出简短的状态复述和计划；确认无误后才编辑文件。
4. 完成一个边界清晰的任务后，更新交接文件，供 Codex 之后反向接手。

## 并发与安全规则

- 同一时间只有一个模型可以写入此工作树。
- 接手模型不可用“清理工作区”方式处理已有修改，不得使用 `git reset --hard`、`git checkout --` 或覆盖未提交文件。
- 未通过的测试必须如实记录；不得写成“已验证”。
- 任何模型切换都以新会话开始；EchoBird 的 Responses 代理会话历史不属于项目状态。

## 验收标准

- 新模型在没有旧会话历史的前提下，能在 5 分钟内确定当前任务、已知限制、工作树状态和下一条验证命令。
- 切换过程不丢失未提交修改，也不泄露密钥或会话标识。
- Codex 与 EchoBird 都遵循相同的项目内交接协议。
